Connecting your phone through your own server

Last updated: 28 October 2026

For your phone to reach Connect on your computer, the two need a network path to find each other. Connect recommends Tailscale by default: install it and you are done, no server required. This page is for the other case: you already have a cloud server and want to run that path yourself.

Running it yourself means the path belongs entirely to you, and the data crossing it only ever moves between your own machines. The cost is fifteen minutes of setup once, after which it mostly looks after itself.

What the relay actually does

Both the phone and the computer dial out to your server, which connects the two sides — rather like two people each phoning the same switchboard.

What matters: the server only forwards. It cannot read any of it. Your terminal output, files and conversations are encrypted before they leave your computer, so the server only ever holds ciphertext it cannot open. It stores nothing, needs no accounts, and never touches your Claude or Codex sign-in.

It also means you do not need to expose any port on your computer to the public internet.

What you need

  • A server reachable from the internet (the cheapest cloud instance is plenty; the relay is tiny)
  • A domain name pointing at it (for example relay.yourdomain.com)
  • Docker installed on that server

If you have all three, the rest takes about fifteen minutes. If you have no server, stay with Tailscale — there is nothing to be gained by forcing this.

Step 1: start the relay

Connect to your server (run this in a terminal on your own computer, with your own address):

ssh your-username@your-server-address

Fetch the relay's deployment files, enter the directory and start it:

git clone https://github.com/K3tty5555/connect-relay.git
cd connect-relay
cp .env.example .env
docker compose up -d --build

-d means it keeps running in the background; closing the ssh window will not stop it.

Step 2: generate a key

This key decides who may use your relay. Without it, knowing the address gets nobody in.

docker compose exec relay node /app/relay-server.mjs keygen

It prints a string beginning with ck_live_. It is shown exactly once — copy it into your password manager straight away. The server keeps only a digest, so a lost key cannot be recovered; you would simply generate a new one.

Do not paste it into chat apps, put it in a URL, or commit it to a public repository.

Step 3: put it behind https

Browsers and phones require an encrypted connection, so the relay needs an address starting with wss:// (think of it as https for this kind of channel).

Caddyfile.example in the repository is a working reference — change the domain to yours and it will obtain a certificate automatically. Two things matter: expose only the /v1/relay path, and never publish the container's port 8787 directly.

Your address will then look like:

wss://relay.yourdomain.com/v1/relay

Step 4: enter it in Connect

On the computer first:

Settings → Mobile remote → expand the advanced settings, and find "External relay":

  1. Address: wss://relay.yourdomain.com/v1/relay
  2. API key: the ck_live_… string you saved in step 2
  3. Click "Save relay"

The two "fallback relay" fields below may stay empty. If you have a second server, fill them in and Connect will switch over automatically when the main path is unreachable.

Then on the phone:

Connect's mobile settings have the same two fields. Enter exactly the same address and key — if they differ at all, the two sides will not meet.

Then pair once by scanning the QR code. Pairing itself can go through your own relay; Tailscale is not required.

If something goes wrong

The phone never connects

Check the address starts with wss:// and ends with /v1/relay, identical on both sides. Then read the log on the server:

docker compose logs -f relay

You want to retire a key

Replace the key file on the server and restart the container; it takes effect immediately:

docker compose restart relay

You want to stop using a relay altogether

Click "Clear relay" in the computer's settings and clear it on the phone too. Both sides fall back to Tailscale or the local network.

Notes

  • The relay offers no account system or admin panel, and never lists your project directories. It is only a path.
  • It forwards encrypted frames only, and can neither read nor retain any of your content.
  • If several people share one relay, generate a separate key for each, so any one of them can be retired on its own.
  • Your server's bandwidth sets how smoothly the phone shows the terminal. Day-to-day use is light, but keep an eye on traffic if you mirror web pages to the phone for long stretches.

Fuller deployment notes (options, key file format, channel self-check) are in DEPLOY.md in the repository. The relay is published under the MIT licence, so you are free to read and modify it: https://github.com/K3tty5555/connect-relay
